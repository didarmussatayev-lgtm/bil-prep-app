# Оплата доступа через Kaspi

Ученик платит за подписку на срок (тарифы правятся в админке → «Оплаты»). После оплаты `User.accessUntil`
продлевается, и материалы открываются. Пока переменная `PAYWALL_ENABLED` не равна `true`, сайт работает
как раньше и никто не платит.

> ⚠️ Приём платежей идёт через [kaspi-pos-automation](https://github.com/tapter-dev/kaspi-pos-automation) —
> неофициальную обёртку над мобильным приложением Kaspi Pay (она входит как iPhone-клиент по SMS кассира).
> Это может нарушать правила Kaspi, а при обновлении приложения Kaspi сервис может перестать работать.
> Поэтому в админке есть ручное подтверждение платежа и ручное продление доступа — резервный путь.

## Как это устроено

```
Ученик ─► /account/subscription ─► POST /api/payments ─► kaspi-pos (qr/create или invoice/create) ─► Kaspi
                                      │                         │
                                      │                         └─ webhook payment.success ─► POST /api/payments/webhook
                                      └─ страница опрашивает GET /api/payments/:id раз в 3 с (резерв, если webhook не дошёл)
```

* Деньги засчитываются один раз: перевод `pending → paid` делается атомарно (`settle()`), поэтому webhook и
  опрос не продлят доступ дважды.
* Webhook публичный, поэтому подпись `X-Webhook-Signature` (HMAC SHA-256) обязательна, а сумма в
  уведомлении должна совпасть с тарифом, иначе платёж помечается «Проверить вручную».
* Ключи Kaspi хранятся только в переменных окружения Railway. В репозитории и логах их нет.

## Настройка

1. **Второй сервис на Railway** из репозитория kaspi-pos-automation. Переменные: `TOKEN_SECRET_KEY`
   (`openssl rand -hex 32`), `PORT`. Файл `webhooks.json`:
   ```json
   [{ "url": "https://<ваш-сайт>/api/payments/webhook", "events": ["payment.success","payment.failed","payment.expired","payment.lost"], "secret": "<KASPI_WEBHOOK_SECRET>" }]
   ```
2. **Вход кассира:** откройте сервис в браузере, войдите по SMS (номер кассира Kaspi Pay). В ответе
   `verify-otp` будут `tokenSN`, `vtokenSecret`, `profileId`.
3. **Переменные этого приложения на Railway:** `KASPI_POS_URL`, `KASPI_TOKEN_SN`, `KASPI_VTOKEN_SECRET`,
   `KASPI_PROFILE_ID`, `KASPI_WEBHOOK_SECRET`.
4. Админка → **Оплаты:** должна быть зелёная строка «Kaspi подключён». Поправьте тарифы.
5. Включите `PAYWALL_ENABLED=true`.

## Что учесть

* **Существующие ученики остаются бесплатными** (`freeAccess=true`). Платными становятся новые ученики,
  созданные при включённой оплате, и те, кого вы переведёте вручную (админка → Оплаты → «Бесплатный доступ»).
* **Сессия кассира может слететь** (вход кассира с другого устройства, обновление Kaspi). Тогда у учеников
  оплата покажет «временно недоступна», а админка — красную строку. Нужно заново войти кассиром и
  обновить `KASPI_TOKEN_SN` и `KASPI_VTOKEN_SECRET`.
* Если деньги пришли, а доступ не открылся — админка → Оплаты → «Пришло» (или «Открыть доступ вручную»).
* Цены по умолчанию (5 000 / 12 000 / 20 000 ₸) — образцы, замените на свои.
