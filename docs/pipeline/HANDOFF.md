## Цель (от заказчика)
Задачи по математике 1–4 были один-в-один с учебником (авторские права). Нужно:
1. Заменить имена на другие казахские, изменить числа, пересчитать ответы, решения и варианты A–E. Номера задач `n` НЕ менять (на них держится прогресс учеников).
2. Задания из `pending` (раньше не загруженные) заменить собственными задачами той же логики.
3. Рисунки-сканы (`kind: "image"`, `kind: "scene"` из `figs/`) не менять — числа на них остаются, меняются только имена/контекст/формулировка.
4. Добавить полный перевод на казахский (теория, условия, варианты, решения), помечается в приложении как непроверенный. Термины сверять с казахской книгой (PDF в корне репозитория).
5. Логика (предмет «Логика») не затрагивается.

## Как устроено приложение (коротко)
- Next.js 14 + Prisma + PostgreSQL на Railway. Переключатель RU/ҚАЗ уже есть (колонка `i18n` у Subject/Section/Topic/Task, `src/lib/i18n/*`).
- Seed (`prisma/seed/index.ts`) сам делает `prisma db push` и грузит темы. Русский контент: `prisma/seed/data/<mathN>/section-K/v2/topic-K-M.ts`. Казахский: `prisma/seed/data/kk/<mathN>-K/K.M.ts`, регистрация в `prisma/seed/data/kk/index.ts` (импорт + запись `"<slug раздела>.<код темы>": ...` в `KK_TOPICS`, название раздела — в `KK_SECTIONS`). Индекс раздела `prisma/seed/data/<mathN>/section-K/index.ts` импортирует `./v2/topic-K-M`.
- Slug-и разделов: math-1, math-2, math-3 (математика 1), math2-1..3, math3-1..2, math4-1..2.

## Инструменты (в репозитории)
```
# выгрузка собранной темы (база+overlay) в JSON; scene/image-рисунки выносятся в figs/<код>.ts
npx tsx prisma/seed/tools-dump.ts math3/section-1 M3_SECTION_1 1.3 <папка_для_json>
#   аргументы: <каталог в prisma/seed/data> <экспорт раздела> <код темы> <папка вывода>
#   экспорты: M3_SECTION_1, M3_SECTION_2, M4_SECTION_1, M4_SECTION_2 (math2: M2_SECTION_1..3; math: SECTION_1..3)
# формат темы
npx tsx prisma/seed/validate.ts prisma/seed/data/math3/section-1/v2/topic-1-3.ts
# сверка с исходным дампом + казахским файлом (числа ru≠kk, нет перевода, скобки, варианты)
npx tsx prisma/seed/tools-check.ts <v2.ts> <kk.ts> <папка_json>/topic-1.3.json
# слепая проверка ответов: выгрузка условий без ответов / сравнение с ответами проверяющего
npx tsx prisma/seed/tools-blind.ts dump <v2.ts> <out.json>
npx tsx prisma/seed/tools-blind.ts cmp  <v2.ts> <ans.json>
npx tsc --noEmit
```
Сухой прогон seed без базы: скопировать `prisma/seed/index.ts` в `_dry.ts`, заменить `new PrismaClient()` на заглушку с `upsert: async()=>({id:"x"})` у subject/section/topic/task и убрать вызов `syncSchema()`; запустить `npx tsx prisma/seed/_dry.ts` (файл потом удалить). Должны напечатать все темы без ошибок.

## Конвейер на одну тему (как делалось для математики 1–2)
1. Выгрузить DUMP (`tools-dump.ts`). Для тем с figs файл `prisma/seed/data/<mathN>/section-K/figs/<код>.ts` создаётся автоматически — его нужно закоммитить.
2. Агент (subagent_type general-purpose) получает задание из `docs/pipeline/BRIEF-mathN.md` (там все правила) + путь к DUMP + выходные файлы. Один агент — 1–3 темы (≈80–120 задач), большие темы (>100 задач) — отдельным агентом, писать файл частями. Параллельно не больше 3–6 агентов, иначе упираемся в лимит сессии.
3. Проверка формата: `validate.ts` (0 ошибок) и `tools-check.ts` (замечаний быть не должно; «числа те же ()» у задач без цифр в условии — допустимо).
4. Слепая проверка ответов: `tools-blind.ts dump` → отдельный агент решает задачи БЕЗ доступа к репозиторию (правила в `docs/pipeline/BLIND.md`), сохраняет `ans-<код>.json` → `tools-blind.ts cmp`. Расхождения разбирать вручную: чаще это ошибка проверяющего или неоднозначная формулировка (тогда уточнить условие в ru и kk). Реальные ошибки ответов исправлять.
5. Завершение раздела: переключить импорты в `section-K/index.ts` на `./v2/topic-K-M`, добавить импорты и записи в `kk/index.ts`, удалить старые файлы `topic-K-M*.ts` (там исходный текст книги) командой `git rm`, `tsc`, сухой прогон seed, коммит, пуш, PR.

## Известные тонкости
- Тесты — `choice` (A–E, ровно один верный, буква = позиция), закрепление — открытые ответы (`ans`). Неправильная дробь: `frac` ругается, использовать `mixed`. Наборы чисел — `set(...)`, порядок — `seq(...)`, выражение — `text(...)` (хрупко: лучше избегать).
- Новые задачи вместо pending получают `n` вида `s1`, `s2`, … (для теста тоже `s…`).
- Подписи внутри рисунков с русским текстом переводятся через поле `figure:` в kk-файле задачи.
- Railway режет логи ~500 строк/с; длинные списки «Проверить вручную» в логе seed могут обрезаться — это не ошибка.
- Если Railway пишет `column ... does not exist` — seed не успел выполнить `prisma db push` (теперь делает сам).
